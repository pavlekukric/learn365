# Product Review — Istorija Srbije 365 (2026-09-28)

**Reviewer:** Claude (five parallel read-only passes: Home/Course/About, Lesson reader + mobile, Backend/auth/sync/ops, Performance/SEO/DX/tests, Content corpus — plus a screenshot walk of the production build at 390 / 1440 / 1920 px and direct verification of the highest-impact claims).
**Build reviewed:** `main` at `9449103` (Phase 8 live on istorija365.com).
**Scope:** everything — UI/UX, copy, content, backend, operations, performance, SEO, accessibility, code quality, tests, docs. Nothing was modified; this document is the only change.
**Previous reviews:** `docs/archive/reviews/UX_AUDIT_CURRENT_UI.md` (overall 7.5/10 when 6 of 365 lessons existed), the 2026-09-25 first-time-experience review (four groups, all shipped).

---

## 1. Verdict

**Overall: 7 / 10.** The visible product is at the level the brief asks for — calm, editorial, coherent on desktop and phone, and all 365 lessons are written in a voice that handles the hard topics (Jasenovac, Srebrenica, Kosovo, Chetniks/Partisans) better than most published popular history. What holds it back from 8+ is not the design: it is the layers under and around it — a 2.4 MB lesson corpus shipped as client JavaScript on every route, no sitemap/canonical while a duplicate origin is still live, a placeholder contact address on the privacy page of a product that now stores accounts, trust scaffolding on 6 of 365 lessons with one citation that looks invented, and a deploy path that rolls out without any CI gate.

Two agents flagged a React hydration mismatch for returning readers. **That finding was tested and rejected** (section 6): the server-rendered `<header>` node survives hydration and no error is reported; the store simply flips from `0 / 365` to `N / 365` one frame later.

## 4. What is right and must be protected

- **The editorial direction.** Every surface reads as one product: Spectral display + Inter UI + mono eyebrows, warm OKLCH palette, hairline rules, the flourish. Do not rebuild any surface; every item above is a targeted fix.
- **The core loop.** `findResumeLesson` drives the hero CTA, the recommended card and the course card; the first-win moment, the promoted next-lesson card and the reduced-motion-aware scroll are all correct. Sign-in is asked once, after the second completion, never as a modal.
- **The auth core.** Authorization code + PKCE, state cookie, SHA-256 session tokens, `Origin` on every mutation, safe `return_to`, no Google tokens stored, real cascading deletion, no PII in logs, no analytics or third-party scripts.
- **The content's honesty.** Day 7 dismantling the "najstarije pismo" myth, Day 250 ("tumačenje, ne činjenica"), Day 341 ("Odgovornost je deljena, ali nije jednaka"), Day 347's Srebrenica paragraph (ICTY/ICJ, "bez umanjivanja, bez izjednačavanja, bez relativizacije"), Day 323's Jasenovac figures, Days 320–322's symmetric treatment of Chetniks and Partisans. Any editorial pass must keep this register.
- **Engineering discipline.** Strict TypeScript everywhere, tested pure logic, clean package seams (content / core / ui / ui-web / web), a dark-deploy Phase 8 that leaves the auth-off app byte-identical, and an isolated compose project on the shared VPS.

## 6. Findings tested and rejected

- **"Returning readers get a React hydration mismatch on every page" (raised by two passes).** Tested on the production build with seeded `learn365:progress:v1`: the server-rendered `<header>` DOM node (tagged before hydration, text `Pročitano 0 / 365`) is the same node after load (text `Pročitano 2 / 365`); zero `console.error`, zero `pageerror`, zero `window.error`, zero `reportError` calls on `/`, `/course/…` and a completed lesson. The store hydrates synchronously but React's first client render matches the server; the flip to `N / 365` happens on the post-hydration render. Cost is a one-frame label flash for returning readers, not an error. No action beyond optionally reserving label width.

## 7. Method

Five independent read-only passes (Home/Course/About + primitives; lesson reader + sidebar + mobile; backend/auth/sync/deploy; performance/SEO/a11y/DX/tests; content corpus with a 12-lesson editorial read and node-based structural audit of all 365 files), then a production build (`next build`, Next 15.5.18, React 19.2.6) walked with Playwright at 390×844, 1440×1000 and 1920×1080 in fresh and seeded-progress states, plus direct spot-checks of every High claim used above (bundle manifest sizes, hydration behaviour, the content slips, reading-time correlation). No production traffic, no file changes other than this document and a pointer in `HANDOFF.md`.
