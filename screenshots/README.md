# History 365 — visual screenshot pack

Automated full-app screenshots for UI/UX review. Generated by Playwright; the
app itself is not modified.

## Run

From the repo root:

```bash
pnpm screenshots
```

That runs:

1. `next build` (production build of `apps/web`)
2. `playwright test --config=playwright.screenshots.config.ts` against a
   `next start --port 3100` server it spins up automatically.

First run also needs the Playwright browsers:

```bash
pnpm --filter @learn365/web exec playwright install --with-deps chromium
```

Output is written to:

```
screenshots/
  desktop/   # 1440 × 1000
  mobile/    #  390 ×  844
```

Image folders are git-ignored; this README is committed.

One PNG per `test(...)` in `capture.spec.ts` per viewport. The former placeholder shot is gone: every lesson is authored (since 2026-05-19).

## What the app does NOT have (so no screenshots exist for them)

The brief asked for several screens that this v1 codebase does not include.
Documenting here so the absence isn't mistaken for a gap in the script:

- **Paywall / subscriptions** — out of scope for v1 (`CLAUDE.md` → "Do not implement
  yet"). Accounts exist since Phase 8 (`/prijava`, `/nalog`), but the pack runs with
  accounts off (no env vars), so those pages are not captured.
- **Settings, notifications, streaks, quizzes pages** — same.
- **Onboarding flow** — no first-run wizard exists; the home page is the entry.
- **Mobile menu in TopBar** — the TopBar is always inline (no hamburger). The
  "Sadržaj" drawer on the lesson page is the closest analogue and is captured.
- **Course outline / timeline as separate drawer** — the timeline is inline on
  the lesson page (≤720px vertical, >720px horizontal); the course outline is
  the sidebar (desktop) or the "Sadržaj" drawer (mobile). Both are already
  visible in `lesson-001` (desktop) and `lesson-001-sadrzaj-drawer` (mobile).
- **Modal/dialog flows** — there are none in v1 user flow apart from the
  lesson drawer.

If those surfaces are added later, extend `apps/web/scripts/screenshots/capture.spec.ts`.

## Test data / setup requirements

- **No env vars → accounts off.** The app renders from the generated content
  modules; the database and Google sign-in stay off without `DATABASE_URL`,
  `APP_URL` and the `GOOGLE_*` values.
- **No DB / API server** to start.
- **Progress state** is seeded via `localStorage` (`learn365:progress:v1`)
  through `addInitScript`, so "with progress" and "completed" shots are
  deterministic. Helper: `apps/web/scripts/screenshots/seedProgress.ts`.
- **Reduced motion** is enabled on the Playwright context so timeline /
  parallax animations don't introduce frame-to-frame diffs.

## Tweaking

- Viewports / project list: `apps/web/playwright.screenshots.config.ts`.
- Screens captured: `apps/web/scripts/screenshots/capture.spec.ts` —
  add a `test(...)` and a `snap(...)` call.
- Output location: `SCREENSHOTS_ROOT` in `capture.spec.ts`.
